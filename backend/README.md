# Backend - DecisionEvents API

Backend for the Steropes project (OpenCV AI Competition 2026). Receives decision events from the AI Agent, stores them in DynamoDB, and serves them to the frontend dashboard.

## Architecture

```
AI Agent  --POST-->  API Gateway  -->  Lambda (Handler)  -->  DynamoDB
Frontend  --GET-->   API Gateway  -->  Lambda (Reader)   -->  DynamoDB
```

## Live Endpoint

Base URL: `https://32v3gb46j5.execute-api.eu-north-1.amazonaws.com/prod`

Full request/response spec: [`backend/api/openapi.json`](./api/openapi.json)

| Method | Path | Purpose |
|---|---|---|
| POST | `/events` | Receive a decision event from the AI Agent |
| GET | `/events/latest?limit=N` | Live feed - most recent events |
| GET | `/events?from=&to=` | Historical range (YYYY-MM-DD) |
| GET | `/events/{request_id}` | Full detail for a single request |
| GET | `/stats?from=&to=` | Tier breakdown + cost-avoided % (defaults to today) |

## DynamoDB Schema

**Table:** `DecisionEvents`

| Attribute | Type | Notes |
|---|---|---|
| `PK` | String | `EVENT#<date>` (e.g. `EVENT#2026-09-01`) |
| `SK` | String | `<timestamp>#<request_id>` |
| `request_id` | String | UUIDv4, generated by the Agent (or auto-generated if missing) |
| `tier_resolved` | Number | 1, 2, or 3 |
| `confidence_breakdown` | Map | `{detection_confidence, tracking_consistency, optical_flow}` |
| `action_taken` | String | `ACCEPT` \| `REPOSITION` \| `ESCALATE` |
| `cloud_cost_avoided` | Boolean | Whether a Bedrock call was avoided |
| `timestamp` | String | ISO-8601 |

**Global Secondary Indexes:**
- `request_id-index` - PK: `request_id` → used by `GET /events/{request_id}`
- `tier_resolved-index` - PK: `tier_resolved`, SK: `timestamp` → used by `GET /stats`

## Lambda Functions

- **`lambda/decision_events_handler.py`** - handles `POST /events`. Converts floats to `Decimal` before writing (DynamoDB requirement).
- **`lambda/decision_events_reader.py`** - handles all GET routes, dispatches based on path/params. Uses GSIs for `request_id` lookup and tier stats instead of full table scans.

Both functions use the Lambda execution role's IAM permissions to access DynamoDB - no credentials are hardcoded or required in the code.

## Local Development

Copy `.env.example` to `.env` and fill in values if you need to run any scripts locally that call AWS directly (most contributors won't need this - the Lambda functions get permissions automatically via their IAM role).

## Testing

All endpoints were manually tested end-to-end via PowerShell (`Invoke-RestMethod`) against the live deployed API, covering:
- Successful writes and reads
- Missing required fields (400 responses)
- Unknown `request_id` (404 response)
- Date range queries spanning multiple days
- Stats aggregation across tiers

## Known Limitations / Next Steps

- Real integration with the AI Agent's actual payloads is pending (schema is agreed and documented, not yet tested against live Agent traffic)
- IAM permissions currently use `AmazonDynamoDBFullAccess` on both Lambdas - to be tightened to least-privilege policies
- Frontend GET endpoint shapes may need small adjustments once frontend requirements are finalized
